## Issues Found (5) — All pending fix in next session

### Issue 1: GCLK/MCLK No Gauge Bars
**Symptom**: GPU Clock (1290 MHz) and Mem Clock (877 MHz) show raw values but no gauge bar underneath.
**Root cause**: `m.max` was set to `undefined` for both metrics in the `allMetrics` array on line 99-100 of `renderer.js`. The bar-rendering logic at line 153 checks `m.max !== undefined` — when undefined, no `<div class="stat-bar">` is emitted.
**Fix needed**: Set `max: 3500` for GCLK and `max: 2500` for MCLK (realistic NVML max clock frequencies). Both should show `% of max` fill + raw MHz overlay on the value.

### Issue 2: Icon Pills Not Selectable
**Symptom**: Clicking on metric icon pills does nothing — no sparkline switching, no visual feedback beyond hover color change.
**Root cause**: CSS `user-select: none` on `body` (style.css line 69) blocks click events. The click handler at renderer.js line 419 uses `e.target.closest('.stat-icon-btn')` but the `<button>` elements have `pointer-events: auto` which should work — need to verify `.stat-icon-btn` has explicit `pointer-events: auto` since body's `user-select: none` can interfere on some browsers.
**Fix needed**: Add `pointer-events: auto` explicitly to `.stat-icon-btn` rule, and verify the click event reaches the handler by checking if any CSS layers block it.

### Issue 3: Sparkline Graphs Not Showing
**Symptom**: Enabling "Show Sparklines" in settings does not produce visible graphs on GPU cards.
**Root causes (3)**:
1. **Data never pushed to render target**: `pushSparklineData()` pushes values into `gpuBuffers` but `renderSparklineSVG()` reads from `gpuSparklines` — two separate objects with no sync between them (this bug was partially fixed earlier but may have regressed).
2. **Buffer initialization timing**: Buffers are only initialized in `pushSparklineData()` which is called from `updateLoop`. If the sparkline toggle fires before any nvidia-smi data arrives, buffers are never created.
3. **Initial render path**: When sparklines are first enabled, `buildGPUCard` must emit the sparkline canvas HTML — but it only does so when `config.showSparklines` is truthy at build time, not after user toggles on.

**Fix needed**: 
- Verify `pushData()` writes to both `gpuBuffers` AND `gpuSparklines` (dual-write)
- Ensure sparkline canvas HTML is always emitted in `buildGPUCard` regardless of config, then hidden via CSS until toggle flips
- Add debug: show "X/2 pts" placeholder when buffer has data but SVG renders blank

### Issue 4: Active Pill Highlight Only Works on Click — Not On Load
**Symptom**: On app start, the Temp pill shows NO highlight (no accent border/background) even though it's the default metric. Only after clicking another icon and clicking back does highlighting work.
**Root cause**: The `sparkline-pill-active` class is only applied when `i === defaultIdx` in buildGPUCard line 171, but `$activeIcon` is set inside the loop while the DOM patch at render time (line 430-432) clears all active classes via `.querySelectorAll('[data-spark-metric].sparkline-pill-active')` and removes them on re-render. After initial build, every `render()` call goes through the patch phase which wipes the active class from icons.
**Fix needed**: In the render patch (or after any re-render), sync back: read `card.dataset.sparkActive` and apply `sparkline-pill-active` to the matching icon pill.

### Issue 5: VRAM Percentage Flashes Then Disappears
**Symptom**: On first render, VRAM briefly shows "XX%" then immediately switches to "27.8 / 32.0 GB" (raw MB only) after ~1 second. Even with "Show VRAM Raw = true", the percentage part is missing — showing only raw values.
**Root cause (two bugs)**:
1. **Config key `showVramRaw` never persisted**: The settings toggle was added to index.html but `config.showVramRaw` was never in DEFAULT_CFG in main.js, so it's always `undefined`. The buildGPUCard VRAM logic checks `config.showVramRaw && ...` which short-circuits on undefined.
2. **Patch phase overwrites value**: The render patch at line 798 (`$vramVal.innerHTML = fmtMiB(...)`) unconditionally writes raw MB to the VRAM stat-value element, wiping whatever was set during initial build (which had both `% + raw`).

**Fix needed**: 
- Add `showVramRaw: true` to DEFAULT_CFG in main.js
- Fix render patch to mirror power's pattern: `displayVal = pct + '%' + span(raw_mb)` when showVramRaw is true

- GCLK/MCLK: gauge uses `% of max clock`, value shows raw MHz alongside gauge fill
- Only the icon pill is selectable — rest of row is display-only
- All changes must be backward-compatible with existing config files
